# AI 도구 활용 내역

## 활용한 AI 도구

본 프로젝트에서는 OpenAI Codex를 개발 보조 도구이자 CADGen-AX의 제품 기능을 구성하는 에이전트 런타임으로 활용하였습니다. 개발 과정에서는 저장소의 개발 원칙을 `docs/AGENTS.md`로 문서화하여 팀원들과 공유하였으며, Codex에도 동일한 문서를 컨텍스트로 제공하였습니다. 이를 통해 개발자와 AI가 공통된 오류 처리, 테스트 및 리뷰 기준을 따르도록 하였습니다.

## 활용 범위

제품에서는 Codex가 사용자의 자연어 요구사항을 구조화된 모델링 계획과 OpenSCAD 코드로 변환하고, Structural·DFM·VLM 검증 결과를 해석하여 다음 설계 수정에 반영하도록 구성하였습니다. 다만 검사 실행 실패와 품질 기준 미통과를 구분하고, 최종 통과 여부와 산출물 이력은 애플리케이션의 명시적인 상태 및 데이터 계약으로 관리하였습니다.

개발 과정에서는 요구사항 및 아키텍처 검토, 기능 구현과 리팩터링, 오류 원인 분석, 테스트 케이스 작성, 문서화에 Codex를 활용하였습니다. 또한 GitHub 이슈의 배경·재현 절차·완료 조건을 구체화하고, PR 설명과 코드 리뷰 초안을 작성하는 데에도 활용하였습니다. AI가 구현 세부 사항을 빠르게 탐색하도록 하는 대신, 팀원들은 기능 간 경계, 상태 전이, 실패 처리 방식과 테스트 전략 등 프로젝트 전체에 영향을 주는 판단에 집중하였습니다.

## AI 생성 코드의 검증 및 수정 방식

AI 생성 코드는 모든 코드를 처음부터 줄 단위로 다시 검토하는 방식보다는 아키텍처 경계, 데이터 계약과 자동화된 테스트를 중심으로 검증하였습니다. 변경 전에는 이슈에 정상·실패·경계 조건과 제외 범위를 명시하였고, 변경 후에는 관련 회귀 테스트와 전체 타입 검사·테스트·빌드를 실행하였습니다. Rust 백엔드, 세션·리비전 영속성, 비동기 작업 및 3D 렌더링과 같이 위험도가 높은 영역은 실패 전파, 상태 복구, 자원 정리와 실제 샘플 동작을 추가로 확인하였습니다. PR 리뷰에서는 AI가 제안한 내용을 실제 코드와 대조한 뒤 필요한 항목만 반영하고, 반영 내역과 검증 결과를 기록하였습니다.

특히 `docs/AGENTS.md`에 정의한 strict fail-fast 원칙을 적용하였습니다. 실패를 숨기는 fallback, 실패 후 빈 결과나 임의의 성공값을 반환하는 동작, 미완성 기능을 정상적으로 동작하는 것처럼 보이게 하는 mock·fake·stub을 제품 코드에 허용하지 않았습니다. 처리할 수 없는 입력과 외부 도구의 실패는 원인을 보존하여 명시적으로 노출하였으며, mock과 stub은 테스트 범위 안에서만 사용하고 테스트 종료 후 복원하였습니다. 최종적으로 AI는 구현 속도와 검토 범위를 확장하는 도구로 활용하되, 아키텍처 결정, 완료 조건 승인과 병합에 대한 책임은 팀원이 담당하였습니다.
